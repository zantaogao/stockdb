【量化系统数据库写入整改方案】

核心目标：解决因多点写入导致的数据库频繁损坏，实现 "API-update only" 机制。

1. 第一阶段：建立只读基线 (Read-Only Baseline)
   - 物理拦截：将所有非更新脚本的 DB 连接改为 read_only=True。
   - 清理写入点：移除训练/评分脚本中的直接写入逻辑，改为输出至本地缓存文件。

2. 第二阶段：构建统一写入网关 (Unified Write Gateway)
   - 白名单制：仅允许 update_tushare_api.py 等少数同步脚本写入。
   - 隔离模式：所有新需求遵循 "临时文件 -> 统一合并 -> 写入DB" 的流程。

3. 第三阶段：鲁棒性保障 (Stability Guard)
   - WAL 自动清理：在连接层增加 WAL 损坏检测与清理。
   - 原子更新：采用 Temp Table 交换模式，避免原表直接大批量操作。
   - 强制备份：写入前自动触发快照备份。

执行路径：
审计写入地图 -> 实现 read_only 开关 -> 迁移写入点至缓存 -> 优化 API 更新逻辑。
